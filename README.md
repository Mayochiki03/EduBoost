# Classroom App (ชื่อโปรเจกต์ชั่วคราว)

ระบบห้องเรียนออนไลน์ สไตล์ Google Classroom + Quizizz สำหรับนักเรียนระดับ ม.ต้น
อ้างอิงแนวทางจาก Tatuga Class ตามตัวอย่างที่ให้มา

**Stack**: Node.js + Express + MongoDB (Atlas) + Cloudinary (เก็บไฟล์) ฝั่ง backend,
React + Vite + Tailwind ฝั่ง frontend, deploy บน Render

## 🐛 Bug fix log

- **[แก้แล้ว] Quiz options หายทุกครั้งที่สร้าง**: model `Quiz.js` ตอนแรกกำหนด schema ของ `options` เป็น `[{ text: String }]` (array ของ subdocument) แต่ controller และ frontend ทั้งหมดส่งข้อมูลเป็น `[String]` (array ของ string ธรรมดา) ตรงๆ ทำให้ Mongoose cast ข้อมูลไม่ตรง schema แล้ว**เงียบๆ ทิ้งข้อมูลเป็น array ว่างโดยไม่ error** — เจอตอนเขียน mock data script แล้วทดสอบ cast จริงเลยรู้ว่าตัวเลือกหายหมด แก้โดยเปลี่ยน schema เป็น `options: [String]` ให้ตรงกับที่ใช้งานจริงทั้งระบบ ทดสอบแล้วว่า cast ถูกต้อง

- **[แก้แล้ว] `Must supply api_key` ตอนอัปโหลดไฟล์**: เกิดจากใน `server.js` เรียก `dotenv.config()` หลัง import routes ต่างๆ ซึ่งใน ES Module import จะถูกรันก่อนโค้ดอื่นเสมอไม่ว่าจะเขียนตำแหน่งไหน ทำให้ `cloudinary.config()` ใน `config/cloudinary.js` (ถูกเรียกตอน import) ได้ค่า env เป็น `undefined` แก้โดยเปลี่ยนเป็น `import "dotenv/config"` เป็นบรรทัดแรกสุดของไฟล์แทน — ทดสอบแล้วว่าค่า `.env` โหลดถูกต้องก่อน routes ทำงาน

รอบนี้เป็นรอบใหญ่ แก้ปัญหาที่เจอจากการใช้งานจริงหลายเรื่องพร้อมกัน สรุปทีละหัวข้อ:

### ✅ เปลี่ยนชื่อแอปเป็น "EduBoost"
เปลี่ยนแล้วทั้ง title หน้าเว็บ, navbar, หน้า welcome (พร้อม tagline "เว็บไซต์บูสต์พลังการเรียนรู้"), ชื่อ package.json ทั้ง backend/frontend

### ✅ แก้ปัญหาบัญชีนักเรียนซ้ำจากการพิมพ์ผิด (ปัญหาใหญ่ที่สุดที่แจ้งมา)
เดิมนักเรียนต้องพิมพ์ชื่อ+เลขที่ใหม่ทุกครั้งที่เข้าห้อง พิมพ์ผิดตัวเดียว (เช่น "10001" เป็น "1001") ระบบเข้าใจว่าเป็นคนละคนแล้วสร้างบัญชีใหม่ทันที ตอนนี้เปลี่ยน flow ใหม่ทั้งหมด:
- นักเรียนกรอกรหัสห้องครั้งเดียว → ระบบโชว์ **รายชื่อทุกคนที่เคยเข้าห้องนี้มาก่อน** ให้เลือก (มีช่องค้นหาชื่อ/เลขที่ด้วย) → กดเลือกชื่อตัวเอง เข้าห้องได้ทันที **ไม่มีการพิมพ์ใดๆ อีกเลย = ไม่มีทางพิมพ์ผิด**
- ถ้าเป็นครั้งแรกจริงๆ ไม่เจอชื่อตัวเองในรายชื่อ กดปุ่ม "ไม่เจอชื่อฉัน / ยังไม่เคยเข้าห้องนี้" แยกออกมาต่างหาก มีคำเตือนให้ตรวจสอบก่อนกดยืนยัน แถมเช็คให้อัตโนมัติว่าเลขที่ซ้ำกับใครในห้องหรือเปล่าก่อนสร้างบัญชีใหม่ (ถ้าซ้ำจะบอกชื่อเจ้าของเลขที่นั้นให้ทันที เผื่อเป็นคนเดิม)
- **ครูลบนักเรียนออกจากห้องได้แล้ว** (เมนู "รายชื่อนักเรียน" มีปุ่มลบ) ใช้ล้างบัญชีซ้ำที่เกิดจากปัญหานี้ก่อนหน้าออกได้เลย ลบพร้อมงาน/คะแนน quiz ของคนนั้นให้อัตโนมัติ

## สถานะปัจจุบัน: v1.1 — แก้บั๊ก Login + ระบบภาพต้นไม้ (Growth Assets) + ปรับ UI

### ✅ ทำเพิ่มจาก v1.0

**แก้บั๊ก login ("เด้งเฉยๆ ไม่รู้เกิดจากอะไร")** — เจอ 2 สาเหตุจริงและแก้แล้ว:
1. `client.js`: axios interceptor เดิม เจอ response 401 ปุ๊บคือ **force reload หน้าไปที่ `/login` ทันที** ไม่ว่า 401 นั้นจะมาจากอะไร — พอกรอกรหัสผ่านผิดตอน login เอง (ก็เป็น 401) หน้าจะรีโหลดทิ้งทันทีก่อนที่ error message จะทันโชว์ เลยรู้สึกเหมือน "เด้งเฉยๆ" ไม่มีคำอธิบาย แก้โดยเช็คว่า request นั้นมี token แนบไปด้วยหรือไม่ก่อนตัดสินใจ auto-redirect (401 จากการ login เอง = ไม่มี token แนบ = ไม่ redirect ปล่อยให้ฟอร์มโชว์ error ตามปกติ)
2. `AuthContext.jsx`: ฟังก์ชัน `login()` เดิมเรียก `refreshUser()` แบบไม่ await แล้วหน้า login ก็ `navigate()` ทันที บางครั้ง React state ยังอัปเดตไม่ทันตอน `ProtectedRoute` render ใหม่ เลยเห็น user เป็น null แล้วเด้งกลับหน้าแรกทั้งที่ login สำเร็จจริง (เป็นสาเหตุของ "บางทีก็ login ไม่ได้ทั้งที่กรอกถูก") แก้โดยทำให้ `login()` เป็น async และ await ให้เสร็จก่อน navigate เสมอ
3. เพิ่ม error message แยกกรณีเชื่อมต่อเซิร์ฟเวอร์ไม่ได้ (ไม่มี `err.response`) ออกจากกรณีรหัสผ่านผิด ให้รู้ชัดว่าปัญหาคืออะไร
4. Trim ช่องว่างหน้า-หลัง email อัตโนมัติก่อนส่ง (กันเคสพิมพ์ผิดจาก autocorrect บนมือถือ/แท็บเล็ต)

**ระบบภาพต้นไม้ (Growth Assets)** — ตามที่ขอ ให้แอดมินอัปโหลดภาพ/GIF เองแทนตัวการ์ตูน SVG เริ่มต้นได้:
- Model ใหม่ `GrowthAsset` เก็บ `{ level, imageUrl }` — ปรับ scale การเติบโตจาก 0-5 เป็น **0-10** ตามที่ขอ (10 ระดับ = 10 ภาพ, ระดับ 0 = ยังไม่ส่งงาน, 10 = โตเต็มที่)
- หน้า Admin เพิ่มเมนู "🌳 ภาพต้นไม้แต่ละระดับการเติบโต" — เห็นช่องอัปโหลดครบทั้ง 11 ระดับ (0-10) พร้อม preview, อัปโหลดทีละระดับแยกอิสระ, ลบรายระดับได้, **รองรับไฟล์ .gif ให้ต้นไม้ขยับได้ตามที่ขอ** (แค่ไฟล์ .gif ธรรมดา ระบบแสดงผลเป็น `<img>` เฉยๆ browser จะเล่น animation ของ gif ให้เองอัตโนมัติ ไม่ต้องเขียนโค้ด animation เพิ่ม)
- ฝั่งนักเรียน/หน้าดูอันดับ: ถ้าแอดมินอัปโหลดภาพของ level นั้นแล้ว จะโชว์ภาพ/gif ที่อัปโหลดแทนที่ตัวการ์ตูนเริ่มต้นทันที ถ้ายังไม่อัปโหลด **fallback กลับไปใช้ตัวการ์ตูน SVG เดิมอัตโนมัติ** ไม่มีจอว่างเปล่าระหว่างที่แอดมินยังอัปโหลดภาพไม่ครบ
- Cache ระดับ frontend กันเรียก API ซ้ำซ้อนหลายจุดในหน้าเดียว พร้อม invalidate cache อัตโนมัติทันทีที่แอดมินอัปโหลด/ลบภาพใหม่

**ปรับ UI ให้ดูเป็นมืออาชีพขึ้น**:
- เพิ่ม `Navbar.jsx` แบบ sticky ด้านบน ใช้ร่วมกันทุกหน้าหลัก (ครู/นักเรียน/แอดมิน) แทน header แบบเดิมที่ทำแยกแต่ละหน้าไม่เหมือนกัน — มี badge บอก role, backdrop blur ตอน scroll

- Modal ทุกจุดเพิ่ม backdrop blur ตอนเปิด (เดิมมีแค่สีดำโปร่งแสง)

## การติดตั้ง (Setup)

### 1. เตรียม MongoDB Atlas
1. สมัคร https://www.mongodb.com/cloud/atlas (ฟรี)
2. สร้าง Cluster (เลือก Free tier M0)
3. สร้าง Database User (username/password)
4. Network Access → Add IP `0.0.0.0/0` (อนุญาตทุกที่ เพราะ Render IP ไม่คงที่)
5. Connect → Drivers → คัดลอก connection string มาใส่ใน `.env`

### 2. เตรียม Cloudinary
1. สมัคร https://cloudinary.com (ฟรี)
2. หน้า Dashboard จะมี Cloud Name, API Key, API Secret — คัดลอกใส่ `.env`

### 3. ติดตั้ง backend
```bash
cd backend
cp .env.example .env
# แก้ไข .env ใส่ค่า MONGO_URI, CLOUDINARY_*, JWT_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD
npm install
npm run seed     # สร้างบัญชีแอดมินคนแรก
npm run dev       # รันเซิร์ฟเวอร์ที่ http://localhost:5000
```

ทดสอบว่ารันสำเร็จ: เปิด `http://localhost:5000/api/health` ควรได้ `{"ok":true}`

### 4. Frontend
```bash
cd frontend
cp .env.example .env
# ค่า default ชี้ไปที่ backend localhost:5000 อยู่แล้ว ปกติไม่ต้องแก้ตอน dev
npm install
npm run dev       # เปิดที่ http://localhost:5173
```
ต้องรัน backend (ขั้นตอนที่ 3) ไว้พร้อมกันด้วย ไม่งั้นหน้า login/join จะเรียก API ไม่ติด

## 📊 เชื่อมต่อ Google Sheets แบบละเอียด

ฟีเจอร์นี้ต้องตั้งค่า 4 ที่ให้ครบ ถ้าพลาดจุดใดจุดหนึ่งจะเชื่อมไม่ติด — จุดที่คนพลาดบ่อยที่สุดคือ **ข้อ 3 (ลืมแชร์ Sheet ให้ service account)**

### ขั้นตอนที่ 1: สร้าง Google Cloud Project + เปิดใช้ Sheets API
1. ไปที่ https://console.cloud.google.com/ (login ด้วย Google account ปกติ)
2. มุมซ้ายบน กด dropdown ชื่อโปรเจกต์ → "New Project" → ตั้งชื่ออะไรก็ได้ เช่น `eduboost-sheets` → Create
3. เลือกโปรเจกต์ที่เพิ่งสร้างให้ active (ดูที่ dropdown บนสุดว่าเป็นชื่อโปรเจกต์ที่สร้างไว้)
4. ค้นหา "Google Sheets API" ในช่องค้นหาบนสุด → กดเข้าไป → กด **Enable**

### ขั้นตอนที่ 2: สร้าง Service Account (บัญชีหุ่นยนต์สำหรับเขียนข้อมูลอัตโนมัติ)
1. เมนูซ้าย (☰) → IAM & Admin → Service Accounts
2. กด "+ Create Service Account"
3. ตั้งชื่อ เช่น `eduboost-sheets-writer` → Create and Continue
4. ขั้น "Grant this service account access" — ข้ามได้เลย (ไม่ต้องตั้ง role) → Continue → Done
5. จะเห็น service account ที่สร้างในรายการ **คัดลอกอีเมลของมันเก็บไว้** (หน้าตาประมาณ `eduboost-sheets-writer@eduboost-sheets.iam.gserviceaccount.com`)

### ขั้นตอนที่ 3: สร้าง Key (รหัสลับให้ backend ใช้ยืนยันตัวตน) + แชร์สิทธิ์ Sheet
1. กดเข้าไปที่ service account ที่เพิ่งสร้าง → แท็บ "Keys" → "Add Key" → "Create new key" → เลือก **JSON** → Create
2. ไฟล์ `.json` จะถูกดาวน์โหลดอัตโนมัติ **เก็บไฟล์นี้ไว้ดีๆ ห้ามแชร์ให้ใคร** เปิดไฟล์ด้วย text editor จะเห็น field ชื่อ `client_email` และ `private_key`
3. **จุดที่พลาดบ่อยที่สุด**: เปิด Google Sheet ที่จะใช้เก็บคะแนน → กด "Share" (แชร์) มุมขวาบน → วางอีเมล service account จากข้อ 2 (เช่น `eduboost-sheets-writer@...gserviceaccount.com`) → ตั้งสิทธิ์เป็น **Editor** → Send/Share — **ถ้าข้ามขั้นนี้ ระบบจะเขียนข้อมูลลง Sheet ไม่ได้เด็ดขาด เพราะ service account เป็นเหมือนบัญชีคนละคน ต้องได้รับเชิญก่อนถึงจะเข้าถึง Sheet ได้**

### ขั้นตอนที่ 4: ใส่ค่าใน `.env` ของ backend
เปิดไฟล์ JSON ที่ดาวน์โหลดมา คัดลอก 2 ค่านี้ไปใส่ใน `backend/.env`:
```dotenv
GOOGLE_SERVICE_ACCOUNT_EMAIL=eduboost-sheets-writer@eduboost-sheets.iam.gserviceaccount.com
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEvQ...(ยาวมาก)...\n-----END PRIVATE KEY-----\n"
```
**ข้อควรระวังเรื่อง `GOOGLE_PRIVATE_KEY`**:
- ต้องคัดลอกมาทั้งหมดรวม `-----BEGIN PRIVATE KEY-----` และ `-----END PRIVATE KEY-----`
- ในไฟล์ JSON ตัวขึ้นบรรทัดใหม่จะเป็น `\n` (แบ็กสแลช-เอ็น) อยู่แล้ว **ห้ามลบออกหรือกดขึ้นบรรทัดจริงแทน** ต้องเป็น `\n` แบบตัวอักษรเหมือนในไฟล์ JSON เป๊ะๆ
- ต้องครอบด้วยเครื่องหมายคำพูด `"..."` ทั้งก้อนเพราะมีช่องว่างและอักขระพิเศษอยู่ข้างใน
- รีสตาร์ท backend (`npm run dev` ใหม่) หลังแก้ `.env` เสมอ (ค่า env จะโหลดแค่ตอนเริ่มรัน)

## 🚀 Deploy ขึ้น Render

### วิธีที่ 1: ใช้ Blueprint (แนะนำ เร็วและง่ายที่สุด)
โปรเจกต์นี้มีไฟล์ `render.yaml` ไว้ที่ root อยู่แล้ว ตั้งค่า service ทั้ง backend+frontend ไว้ให้พร้อม
1. Push โค้ดทั้งโปรเจกต์ขึ้น GitHub (ต้องมี `render.yaml` อยู่ที่ root ของ repo)
2. ไปที่ https://dashboard.render.com/ → กด "New +" → "Blueprint"
3. เลือก repo ที่ push ไว้ → Render จะอ่าน `render.yaml` แล้วสร้าง 2 services ให้อัตโนมัติ (eduboost-backend, eduboost-frontend)
4. Render จะถามให้กรอกค่า environment variables ที่ตั้ง `sync: false` ไว้ (MONGO_URI, CLOUDINARY_*, ADMIN_EMAIL, ADMIN_PASSWORD, ฯลฯ) — กรอกค่าจริงตอนนี้เลย ส่วน `JWT_SECRET` ระบบสุ่มให้อัตโนมัติไม่ต้องกรอก
5. กด "Apply" รอ build เสร็จทั้งสอง service (ครั้งแรกใช้เวลาสัก 3-5 นาที)
6. หลัง deploy เสร็จ จะได้ URL 2 อัน (เช่น `https://eduboost-backend.onrender.com` และ `https://eduboost-frontend.onrender.com`) — กลับไปแก้ env vars อีกรอบ:
   - ที่ service `eduboost-backend`: ตั้ง `CLIENT_URL` เป็น URL ของ frontend
   - ที่ service `eduboost-frontend`: ตั้ง `VITE_API_URL` เป็น URL ของ backend **+ `/api`** ต่อท้าย (เช่น `https://eduboost-backend.onrender.com/api`) แล้วต้อง **Manual Deploy → Clear build cache & deploy** ใหม่ เพราะ Vite ฝัง env เข้าไปตอน build ไม่ใช่ตอนรัน เปลี่ยนค่าแล้วต้อง build ใหม่เสมอ

### วิธีที่ 2: สร้างเองทีละ service (ถ้าไม่อยากใช้ Blueprint)
**Backend:**
1. New + → Web Service → เลือก repo → ตั้งค่า:
   - Root Directory: `backend`
   - Build Command: `npm install`
   - Start Command: `npm start`
2. ใส่ environment variables ทั้งหมดตามที่อยู่ใน `backend/.env.example`

**Frontend:**
1. New + → Static Site → เลือก repo → ตั้งค่า:
   - Root Directory: `frontend`
   - Build Command: `npm install && npm run build`
   - Publish Directory: `dist`
2. ใส่ `VITE_API_URL` ชี้ไปที่ backend URL + `/api`

### ข้อควรรู้เรื่อง free tier ของ Render
- Web Service แบบฟรีจะ **sleep เมื่อไม่มีคนใช้งาน** พอมีคนเข้าครั้งแรกจะช้าประมาณ 30-50 วินาที (cold start) เป็นเรื่องปกติ ไม่ใช่ error
- ถ้าอยากให้ backend ตื่นอยู่ตลอด ต้องอัปเกรดเป็น paid plan ($7/เดือน) หรือจะปล่อยฟรีแบบมี cold start ก็ได้ถ้ารับได้กับความหน่วงตอนเปิดครั้งแรก
- Static Site (frontend) ไม่มีปัญหา sleep เพราะเป็นไฟล์ static ล้วนๆ

## ⚠️ สิ่งที่ควรทำก่อนใช้งานจริงกับนักเรียน (security checklist)

- **ปิดหรือจำกัด `POST /api/auth/register`** — ตอนนี้ endpoint นี้เปิดเผยสาธารณะ ใครก็สมัครเป็นครูได้ ใช้แค่ตอน setup ครั้งแรก (สร้างครูคนแรกผ่าน `npm run seed` แทนได้เลย ไม่จำเป็นต้องใช้ endpoint นี้อีก) แนะนำ comment บรรทัด `router.post("/register", ...)` ออกใน `authRoutes.js` หลัง setup เสร็จ แล้วสร้างครูคนอื่นผ่านหน้า Admin Panel (`/admin`) แทน
- เปลี่ยน `JWT_SECRET` ใน `.env` เป็นค่าสุ่มยาวๆ ห้ามใช้ค่าตัวอย่าง (ถ้า deploy ผ่าน `render.yaml` ระบบสุ่มให้อัตโนมัติอยู่แล้ว)
- ตั้งรหัสผ่านแอดมิน (`ADMIN_PASSWORD`) ให้รัดกุม ไม่ใช่ค่าตัวอย่างใน `.env.example`
- จำกัด Network Access ของ MongoDB Atlas ให้แคบลงถ้าเป็นไปได้ (ตอน dev ใช้ `0.0.0.0/0` เพื่อความสะดวก แต่ถ้ารู้ IP ของ Render แน่นอนแล้วควรจำกัด)
- **อย่าแชร์ค่าใน `.env` (รหัสผ่าน DB, Cloudinary secret, ฯลฯ) ในที่แชทหรือที่สาธารณะ** ถ้าเผลอแชร์ไปแล้วให้เปลี่ยนรหัส/regenerate key ใหม่ทันที
